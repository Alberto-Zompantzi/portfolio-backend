## Architecture Grade Summary

Portfolio Backend implements a **strict N-Tier / Layered Architecture** with explicit separation of concerns between HTTP transport, business logic, and persistence. The service layer is **interface-driven**, the transport contract uses **DTO decoupling** (entities never leave the JVM boundary), and every inbound payload passes through **Jakarta Bean Validation** before reaching the domain.

### Engineering Standouts

- **Zero-Entity-Leak Policy:** Transport uses `ContactoDTO`; manual adapter maps to `Contacto` entity at the service layer — database internals never serialize over the wire.
- **Auditable Timestamps:** `@PrePersist` lifecycle hook stamps `fechaRegistro` at the entity layer, guaranteeing server-clock consistency regardless of client-supplied data.
- **12-Factor Credentialing:** All datasource configuration (`DATABASE_URL`, `DATABASE_USER`, `DATABASE_PASSWORD`) is injected exclusively via environment variables — zero properties-file secrets.
- **Global cross-origin policy for SPA + mobile client integration without separate gateway:** CORS is handled at the controller level to support Cloudflare Pages SPA and future mobile clients.
- **Render-Optimized Docker Image:** Eclipse Temurin 21 Alpine base + single `bootJar` stage produces a small, fast-starting container compatible with Render's Web Service runtime.
- **OpenAPI 3 Autodoc:** SpringDoc 2.8.5 scans the controller layer and emits `/v3/api-docs` + interactive Swagger UI with zero handwritten YAML.

## 🚀 Core Features Breakdown

| Section            | Feature                            | Technical Pattern                                                                            |
| ------------------ | ---------------------------------- | -------------------------------------------------------------------------------------------- |
| **HTTP Transport** | Versioned API surface              | `/api/v1/contactos` prefix + `@RestController` stereotype                                    |
| **HTTP Transport** | Contact message ingestion          | `POST` endpoint with `HttpStatus.CREATED` (201) semantic                                     |
| **HTTP Transport** | Synthetic health probe             | `GET /health` → returns plain-text liveness signal for Render LB                             |
| **Validation**     | Inbound contract enforcement       | `@Valid` on controller param + Jakarta `@NotBlank` / `@Email` on DTO fields                  |
| **Validation**     | Fast-fail 400 on malformed payload | Spring `MethodArgumentNotValidException` → default RFC-7807 problem response                 |
| **DTO Layer**      | Entity boundary isolation          | `ContactoDTO` (transport) ≠ `Contacto` (persistence) — no shared object                      |
| **Service Layer**  | Interface-driven contract          | `ContactoService` interface → `ContactoServiceImpl` concrete bean                            |
| **Service Layer**  | Manual DTO → Entity mapping        | Explicit setter calls; no reflection-based mapper for deterministic behavior                 |
| **Persistence**    | Standard JPA repository            | `ContactoRepository extends JpaRepository<Contacto, Long>`                                   |
| **Persistence**    | Auto-generated PK                  | `@GeneratedValue(strategy = IDENTITY)` — Postgres SERIAL-compatible                          |
| **Persistence**    | Server-side timestamp              | `@PrePersist` sets `LocalDateTime.now()` — immune to client clock drift                      |
| **Persistence**    | Unlimited message length           | `columnDefinition = "TEXT"` for `mensaje` — no arbitrary varchar truncation                  |
| **Config**         | Env-vars-only datasource           | `${DATABASE_URL}` / `${DATABASE_USER}` / `${DATABASE_PASSWORD}` in `application.yml`         |
| **Config**         | Profile-aware bootstrap            | `SPRING_PROFILES_ACTIVE` defaults to `dev` — prod swaps behavior via Render env              |
| **OpenAPI**        | Autogenerated spec + UI            | SpringDoc starter → `/v3/api-docs` + `/swagger-ui/index.html`                                |
| **CORS**           | SPA + mobile integration           | Controller-level global cross-origin policy without separate gateway                         |
| **Container**      | Alpine-based JDK image             | `eclipse-temurin:21-jdk-alpine` — minimal attack surface + fast pull                         |
| **Container**      | Single-stage bootJar build         | Gradle `bootJar` runs inside Docker — host Gradle install not required                       |
| **Compose**        | Local Postgres 17 Alpine           | Named volume + 5432 port binding — identical to Neon/Supabase-style managed provider dialect |

### Option 1 — Quick Local (Docker Compose, Postgres only)

Run Postgres in Docker and start the Spring Boot app **directly on the host JVM**. Best for fast dev-loop.

```bash
# 1. Clone & enter
git clone https://github.com/Alberto-Zompantzi/portfolio-backend.git
cd portfolio-backend

# 2. Start Postgres 17 Alpine container (data persisted in named volume)
docker compose up db -d

# 3. Set env vars pointing to the Compose Postgres — NEVER commit credentials
export DATABASE_URL="jdbc:postgresql://localhost:5432/<local-db>"
export DATABASE_USER="<local-user>"
export DATABASE_PASSWORD="<local-pass>"
export SPRING_PROFILES_ACTIVE="dev"

# 4. Run the app (Gradle Wrapper downloads itself first run)
./gradlew bootRun           # Linux / macOS
# or
.\gradlew.bat bootRun       # Windows PowerShell / CMD

# 5. Verify
curl http://localhost:8080/api/v1/contactos/health
# → "Servidor despierto y listo."
```

> Open [http://localhost:8080/swagger-ui/index.html](http://localhost:8080/swagger-ui/index.html) for interactive API playground.

### Option 2 — Docker / Docker Compose (Full stack: App + DB)

Everything containerized — identical to Render's production runtime.

```bash

```

## ☁️ Deployment Guide (Production)

### Target Platform — Render Web Service (Dockerfile deploy)

```yaml
# Runtime config · Set via Render Dashboard → Environment
SPRING_PROFILES_ACTIVE=prod
DATABASE_URL=jdbc:postgresql://<managed-host>:5432/<managed-db>   # Neon/Supabase-style managed Postgres provider
DATABASE_USER=<managed-user>
DATABASE_PASSWORD=<managed-pass>
```

| Step | Action                                                                                           |
| ---- | ------------------------------------------------------------------------------------------------ |
| 1    | In Render → **New +** → **Web Service** → connect `portfolio-backend` repo                       |
| 2    | **Runtime** → `Docker` (Render picks up Dockerfile at root automatically)                        |
| 3    | **Build Command** → _(leave empty · Dockerfile handles in-container `bootJar`)_                  |
| 4    | **Start Command** → _(leave empty · ENTRYPOINT in Dockerfile wins)_                              |
| 5    | **Instance Type** → Starter / Starter Plus (heap pinned to match container ceiling)              |
| 6    | **Environment → Secret Files** → paste the 4 env vars above (never commit to `.env`)             |
| 7    | **Advanced → Health Check Path** → `/api/v1/contactos/health` (Render LB polls this)             |
| 8    | Hit **Create Web Service** · wait for `==> OpenAPI spec available at /v3/api-docs` in deploy log |
| 9    | Open `<your-render-host>/swagger-ui/index.html` to validate the deployed surface                 |

### Production Hardening Roadmap

| Priority | Hardening Step                                                        | Pattern Applied                                                                                       |
| -------- | --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| **P0**   | Swap `ddl-auto: update` for explicit schema migrations                | Flyway/Liquibase migrations + validate mode — Hibernate no longer touches DDL in prod                 |
| **P0**   | Disable `show-sql` & `format_sql` in prod profile                     | Set `spring.jpa.show-sql: false` + log level `WARN` for `org.hibernate.SQL`                           |
| **P1**   | Restrict CORS from wildcard to explicit SPA origin list               | Register a `CorsConfigurationSource` bean with allowed-origins = Cloudflare Pages domain(s)           |
| **P1**   | Inject DB credentials via Render Secrets instead of env vars          | Use Render **Secret File** → mounted at runtime; avoids env inspect leaks                             |
| **P1**   | Add `server.error.include-stacktrace=never` & `include-message=never` | Suppress stack traces & internal detail leaking over HTTP error responses                             |
| **P2**   | Add rate limiting on POST /contactos                                  | Bucket4j or Resilience4j rate limiter on controller endpoint (mitigate form spam / brute-force)       |
| **P2**   | Add structured JSON logging + Render Log Stream                       | `Logback` JSON encoder → `net.logstash.logback:logstash-logback-encoder`                              |
| **P2**   | Hikari pool fine-tuning                                               | Serverless-aware Hikari pool tuning pattern — match `maximum-pool-size` to managed DB max_connections |
| **P3**   | Add input sanitization on `mensaje` / `asunto`                        | OWASP `java-html-sanitizer` strip → prevent stored markup injection risks                             |
| **P3**   | Add contact-message dedup window                                      | Same `email` + same `mensaje` hash + 5-min TTL cache → 409 Conflict on retry storms                   |

## 📊 Production Quality Gates (Measurable Pattern-Based)

| Signal                       | Current                                       | Rationale                                                                                                                  |
| ---------------------------- | --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **Entity Leakage**           | ✅ Zero — DTO/Entity boundary enforced        | `ContactoDTO` (transport) is a separate Lombok `@Data` POJO; controller never returns `Contacto` before service adaptation |
| **Hardcoded Credentials**    | ✅ Zero — 12-Factor injection                 | `application.yml` uses `${DATABASE_URL}` / `${DATABASE_USER}` / `${DATABASE_PASSWORD}` placeholders exclusively            |
| **Bean Validation Coverage** | ✅ 3/4 mandatory fields validated             | `nombre` (@NotBlank), `email` (@NotBlank+@Email), `mensaje` (@NotBlank) — only `asunto` is optional by design              |
| **Automated Build**          | ✅ Reproducible Docker build                  | `bootJar` runs inside `eclipse-temurin:21-jdk-alpine` — no dependency on host JDK version                                  |
| **DB Schema Drift Risk**     | ⚠️ Medium (`ddl-auto: update` in current yml) | **Prod gate:** switch to `validate` + Flyway/Liquibase migrations before go-live                                           |
| **API Spec Drift**           | ✅ SpringDoc scans code first                 | No hand-written YAML; spec is generated from live controller/beans — impossible to diverge from runtime                    |
| **Test Coverage (Smoke)**    | ✅ `contextLoads` SpringBootTest present      | Zero runtime config regressions on dependency upgrades                                                                     |
| **Container Size**           | ✅ Alpine JDK base (not distroless but small) | Swap to `eclipse-temurin:21-jre-alpine` + separate builder stage to cut ~50% image size                                    |
| **Observability (Liveness)** | ✅ `/health` endpoint wired to Render LB      | Render's auto-restart kicks in after 3 consecutive failures                                                                |
| **CORS Footprint**           | ⚠️ Wildcard origin policy                     | **Prod gate:** narrow to explicit SPA domain(s) before exposing public form                                                |
